# 봄버스터즈

기존 NestJS 인메모리 방 / Socket.IO `/game` / React 게임 선택 구조에 `bomb-busters`를 추가했다. 별도 DB 마이그레이션이나 새 런타임 의존성은 없다. Railway의 기존 백엔드 빌드와 Vercel의 기존 프론트엔드 빌드를 그대로 사용한다.

## 규칙 출처와 지원 범위

다운로드 폴더의 **봄 버스터즈 한국어 규칙서. 이 파일 다운 받으면 좋아요 눌러야 됨.pdf** 8쪽 전체를 확인했다. 세부 예외는 제작사의 [영문 규칙서](https://www.cocktailgames.com/wp-content/uploads/2023/10/BombBusters_rules_EN.pdf), [공식 FAQ](https://www.cocktailgames.com/nos-jeux/bomb-busters-faq/), [공식 구성물 사진](https://www.cocktailgames.com/wp-content/uploads/2023/10/Bombbusters.zip)으로 확인했다. 원본 그림이나 PDF는 저장소에 복제하지 않는다.

기본판 **미션 1–66 전체**, 공용 장비 18종과 추가 개인 장비를 지원한다. 방장은 대기실의 임무 선택에서 미션을 바꿀 수 있다. 훈련 1은 파란 1–6 각 4개이며, 훈련 2는 1–8, 훈련 3은 1–10, 이후는 1–12를 사용한다. 인원별 빨강·노랑 구성과 후보 개수는 각 미션 설정에서 적용한다. `missionId: 0`은 공식 번호 미션과 별개인 자유 연습이다.

음성 미션 19·30·42·54·66은 한국어 화면 안내와 서버 타이머로 진행한다. 원본 MP3 자동 재생 기능은 아니며, 설명 확인 뒤 작업시간을 시작한다. 66번에는 양면 벙커 지도와 이동·행동 선택이 있다. 원음과 디지털 처리의 차이와 명시되지 않은 예외의 해석은 [음성 미션 분석](bomb-busters-audio-rules.md)과 [구현 기록](bomb-busters-implementation.md)에 남겼다.

후속 조사에서 **1~66번 카드 앞뒷면 132장**과 추가 구성물 자료를 확보했다. [미션별 규칙 요약과 원본 링크](bomb-busters-missions.md), [제약·도전·장비·공식 음원 자료](bomb-busters-mission-components.md)에 정리했다. 캠페인 전체의 구현·검증 상태는 [단계별 구현 기록](bomb-busters-implementation.md)에 기록한다.

## 구현 규칙

- 기본은 2~5인 협력이며 일부 미션의 최소 인원과 특수 배분은 미션 지시를 우선한다. 2인은 각 2개 스탠드, 3인은 캡틴만 2개, 4~5인은 각 1개. 스탠드마다 균등 배분하고 각각 오름차순 정렬한다. 두 스탠드는 한 사람의 손패다.
- 무작위 캡틴부터 순서대로 자기 파란 전선 하나에 정보 토큰을 놓는다. 자기 값만 보이고 동료의 값은 숨긴다. 잘린 전선의 자리는 유지한다.
- 이중 절단은 자기 전선 하나와 동료 전선 하나를 선택한다. 같은 값이면 둘 다 절단한다. 오답이면 대상의 실제 값에 정보 토큰을 놓고 다이얼이 1칸 움직인다. 대상이 빨간색이면 즉시 실패한다.
- 다이얼은 **참가 인원 수번째 오답**에 폭발한다.
- 단독 절단은 그 값의 남은 전선 전부 (2개 또는 4개)를 혼자 가지고 있어야 한다. 노란 전선은 정렬용 소수와 관계없이 모두 같은 값이다.
- 자기 손에 빨간 전선만 남으면 안전하게 공개한다. 빈 손의 차례는 건너뛰며, 모든 스탠드가 비면 성공한다.
- 개인 더블 탐지기는 미션당 1회. 파란 숫자를 선언하고 한 동료의 **같은 스탠드**에서 두 전선을 선택한다. 둘 다 빨간색이면 폭발한다. 성공 시 일치하는 전선 하나, 실패 시 비빨간 전선 하나를 대상 소유자가 결정한다. 후보가 한 개여도 동일한 확인 절차를 거쳐 정답 개수나 빨간색 여부를 외부에 노출하지 않는다.
- 기본 공용 장비 1–12는 해당 번호 파란 전선 2개가 잘리면 사용 가능하며 각 1회다. 교환·표식·탐지·재충전·안정기·되감기·커피잔을 각 카드의 시점과 효과에 맞게 처리한다. 공용 장비와 개인 장비의 사용 횟수는 독립적이다.
- 대화로 손패 값/위치를 알리거나 추측을 전달하지 않도록 화면에 안내한다. 별도 자유 채팅은 추가하지 않았다.

캠페인의 숫자·순서·제약·도전 카드, 특수 정보 토큰, 역방향·X 전선, 산소·나노 진행과 음성 사건은 각 미션의 서버 규칙으로 처리한다. 화면에는 해당 미션에서 가능한 행동과 준비 단계만 표시한다. 기본 절단·승리 규칙보다 각 미션의 예외 규칙을 우선한다.

## 연결과 비공개 정보

방장은 대기실에서 `select_bomb_mission`으로 미션을 선택한다. 변경하면 다른 참가자의 준비 상태를 해제하여 변경된 조건을 확인하게 한다. `bomb_busters_action`으로 행동을 보내면 서버가 참여자·차례·대상·도구·남은 전선을 검증한다. 거부한 명령은 부분 적용하지 않으며, 서버 시간 경과에 따른 만료는 명령의 성공 여부와 별개로 적용한다. 상태는 `game_started`, `bomb_busters_state_updated`, `game_ended`로 플레이어별 전송한다. 오류 이벤트는 `bomb_busters_error`다.

확정된 행동 결과는 선택적 `feedback: { id, kind }`로 전달한다. 전선 식별자나 숨은 값은 포함하지 않으며, 클라이언트는 새 결과에만 성공·실패 시각 효과를 재생한다. 초기 접속과 재접속의 첫 상태는 기준점으로만 사용한다.

게임 방의 기본 직렬화는 봄버스터즈 원본 상태를 반환하지 않는다. HTTP 조회는 공개 정보만, 소켓 조회/갱신은 해당 세션의 개인 정보만 반환한다. 와이어 식별자는 값과 무관한 UUID다. 게임 종료 후에는 전체 손패를 공개한다.

첫 소켓 입장 시 개인 재접속 토큰을 발급하고 브라우저 탭의 `sessionStorage`에 저장한다. 다른 소켓은 같은 `playerId`라도 이 토큰 없이 그 플레이어로 입장할 수 없다. 재접속 유예 시간은 기존과 같은 30초다. 명시적 퇴장 또는 유예 시간 만료로 구성원이 빠지면 손패 구성이 성립하지 않으므로 방 전체를 대기실로 되돌린다. 게임이 끝나면 방장만 대기실로 복귀시킬 수 있다.

인메모리 저장 방식은 기존 구조와 같다. 백엔드 재시작 시 방과 게임이 사라지며, 여러 백엔드 인스턴스 간 방 상태 공유는 지원하지 않는다.

## 검증

```sh
cd backend
npm ci
npm test

cd ../frontend
npm ci
CI=true npm test -- --watchAll=false --runInBand
CI=true npm run build

cd ../backend
npm run test:socket
```

서버 테스트는 인원별 배분·비공개 정보·절단·탐지기·장비·실패/승리·잘못된 행동의 원자성·소켓 권한·재접속·퇴장을 검증한다. 프론트 테스트는 숨김 전선·단서·행동 전송·탐지기 소유자 선택·차례 밖 장비·결과 화면을 검증한다. `test:socket`은 임시 로컬 서버에서 훈련 1–8과 자유 연습을 2–5인으로 승리까지 진행하며, 캠페인의 미션 선택·준비·개인별 정보·재접속·복귀를 확인한다. 토이배틀·노터치크라켄의 시작·복귀도 포함한다. 앞서 프론트 의존성을 설치해야 하며 로컬 포트를 열 수 있는 환경에서 실행한다.
